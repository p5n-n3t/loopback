## Capture budget for the implementing agent

- First compare source changes with `covers` in the live verification set. This JSON is a portable index, not a replacement for live freshness checks.
- Reuse matching labels. Re-capture only changed or missing views.
- Prefer one desktop approval-detail view and one representative mobile view for layout work.
- Add discovery-stage evidence only for new states that the existing screenshots cannot show.
- Use recordings only for transient states or motion that stills cannot establish.
- Respect the active `/proof` skill and required evidence. Efficiency does not waive required verification.
- In Lightsprint, capture the real preview with server-side tools. Do not install a browser just to capture pages.
- If another account lacks those tools, use its supported verification path and report any harness limitation. Do not claim missing captures passed.
- Never reuse screenshot cookies or fixture authorization URLs from an old sandbox. Seed a fresh sandbox session by supported data/runtime means.
