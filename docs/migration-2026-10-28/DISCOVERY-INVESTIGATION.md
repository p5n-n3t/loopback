## Interpretation to preserve in handoff

“Registered managed binding” means an entry in `bindings.json` with Loopback-owned per-binding state. It says nothing about unrelated processes or pre-existing OS routes. “Registered worker” means an SSH target in `workers.json` and/or a binding target; installation records targets after an explicit install. Neither set is complete system discovery. Tailscale peer discovery (`tailscale status --json`) is host inventory only; it has no Serve/Funnel handler/path information. Existing ingress status checks only the configured Loopback port and reports managed status.

The observed single topology service is consistent with source and checkpoint: topology adds one service node per `manager.bindings()` row. If only `ora1-system` is registered, that is all it can show as a service. Seven installed workers are not seven managed service bindings. Existing RotoXY route protection is a safety invariant, not proof of route discovery or display.
